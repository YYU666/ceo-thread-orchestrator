# Game Responsibilities

Select a responsibility only for an actual task. Combine responsibilities or reuse
existing lanes within CEO Flow staffing. Every executor returns evidence to the
existing CEO; this file creates no agents, Goals, producers, or approval hierarchy.

## Design

Input: current game intent, player feedback, constraints. Output: a concrete playable
slice with actions, feedback, done criteria, and non-goals. Confirm dependencies with
level/gameplay work instead of handing over a broad design document.

## Level

Input: approved slice and area constraints. Output: a traversable region/route with
layout and collision evidence, then scoped decoration. Respect locked/manual areas.

## Gameplay

Input: explicit behavior and available engine tools. Output: working gameplay through
existing tools/recipes; for a proven gap, a bounded engine patch with focused tests.

## Art and audio

Input: named gaps, style/size/animation/audio requirements, and asset inventory.
Output: reusable or explicitly authorized new assets integrated into the scenario,
with source/license references and preservation of existing accepted assets.

## QA

Input: current candidate, required observations, and existing evidence. Output:
risk-proportionate play/edit/persistence/export evidence and reproducible defects.
Avoid rerunning unchanged checks or accepting test counts in place of the scenario.
